## 0.1.0

### Minor Changes

- [#89](https://github.com/prefactordev/typescript-sdk/pull/89) [`78df699`](https://github.com/prefactordev/typescript-sdk/commit/78df69985e614c0ed658ea7ed5837f37efce6f50) Thanks [@joshgillies](https://github.com/joshgillies)! - Add `@prefactor/pi`, a pi extension that records each pi session in Prefactor as an agent instance, with spans for agent runs, LLM responses (including cache token counts and cost) and tool calls. Install it with `pi install npm:@prefactor/pi` and supply credentials through extension options, the `PREFACTOR_*` environment variables or a `prefactor.json` file in pi's agent directory (`~/.pi/agent` by default, or the directory set by `PI_CODING_AGENT_DIR`).

- [#90](https://github.com/prefactordev/typescript-sdk/pull/90) [`e133514`](https://github.com/prefactordev/typescript-sdk/commit/e133514dae55b26d8ef1c30fc9edd0e63e590827) Thanks [@joshgillies](https://github.com/joshgillies)! - Add `/prefactor setup`, `/prefactor status` and `/prefactor logout` to the pi extension. `/prefactor setup` connects pi to Prefactor through browser sign-in, with the code, link and QR code shown inside pi. It lets the user choose or create the agent, saves an agent-deployment token to `~/.pi/agent/prefactor.json` with mode `0600`, and revokes the sign-in's account token. Users no longer need the Prefactor CLI or to copy a token by hand. A pasted deployment token is the fallback when browser sign-in is unavailable.

- [#91](https://github.com/prefactordev/typescript-sdk/pull/91) [`038ac6f`](https://github.com/prefactordev/typescript-sdk/commit/038ac6f1749bb18bed8369ec13a9a0efd4eca5d9) Thanks [@joshgillies](https://github.com/joshgillies)! - Let agents built on pi's SDK set the recorded agent version with the `agentVersion` option of `prefactorExtension()`. When it is not set, the version of the pi framework is recorded. The README and a new example show how to load the extension through `extensionFactories` so each session is recorded as one agent instance.

### Patch Changes

- [#98](https://github.com/prefactordev/typescript-sdk/pull/98) [`bc96537`](https://github.com/prefactordev/typescript-sdk/commit/bc9653780696a425adee51a49930c78816ef5c0a) Thanks [@joshgillies](https://github.com/joshgillies)! - Record pi sessions with Prefactor's canonical agent span types, so each session opens in Prefactor's conversation view. Inside the `pi:session` root span, the extension now records the system prompt when it changes, a user turn with its user message for every prompt, steering and follow-up message, and an assistant turn holding each LLM call, its thinking and text blocks, and the tool executions, with token usage in the canonical fields. Each tool pi has at session start gets its own span type, and tools added later use a fallback type. The `pi:agent_run`, `pi:llm` and `pi:tool*` span types are gone.

- [#99](https://github.com/prefactordev/typescript-sdk/pull/99) [`0777c39`](https://github.com/prefactordev/typescript-sdk/commit/0777c3943b3ba3006d4bd3d51881cc173c6673a1) Thanks [@joshgillies](https://github.com/joshgillies)! - Let agents built on pi's SDK add to what `@prefactor/pi` records. `prefactorExtension()` now takes extra span types, quality schemas and alert schemas, and per-tool span type details that keep each tool's `$agent:tool:<name>` type. Its `onSessionStart` option receives a recorder for the session, which opens custom spans in the session's span tree and records quality and raises alerts on the session's agent instance with the agent-deployment token. The agent version is identified by the `agentVersion` option, and the extension no longer sends a name or description for it, which Prefactor does not store.

  `@prefactor/core` gains `alert_schemas` on `AgentSchemaVersion` (the `AlertSchema` type) and `AgentInstanceClient.raiseAlert()`, so alerts can be declared and raised on an agent instance without calling the API directly.

- [#100](https://github.com/prefactordev/typescript-sdk/pull/100) [`25e6b33`](https://github.com/prefactordev/typescript-sdk/commit/25e6b33f592de7cec752c3ef38ac666f5ed110f5) Thanks [@joshgillies](https://github.com/joshgillies)! - Let agents built on pi's SDK tie each session's agent instance to an outside run and say how the session ended. The new `externalIdentifier` option of `prefactorExtension()` sets the agent instance's external identifier, as a string for a process that runs one session or as a function called at each session start; Prefactor requires the identifier to be unique per agent. The session recorder's new `setFinishStatus()` sets whether the instance finishes as complete, failed or cancelled at session shutdown, and the instance still finishes as complete when nothing sets it. The `pi` command records exactly what it did before.

- [#96](https://github.com/prefactordev/typescript-sdk/pull/96) [`ed1ed77`](https://github.com/prefactordev/typescript-sdk/commit/ed1ed775cf9c066383c964ee693118e7025123bd) Thanks [@joshgillies](https://github.com/joshgillies)! - Save the account id when `/prefactor setup` uses a pasted agent-deployment token, so `/prefactor status` shows the account as well as the agent. A deployment token cannot read the agent's or account's name, so `agent_name` and `account_name` are saved only by browser sign-in, and the README now says which credentials-file fields are optional.

- [#94](https://github.com/prefactordev/typescript-sdk/pull/94) [`8165785`](https://github.com/prefactordev/typescript-sdk/commit/8165785b1fa0b21524c9c8fa5447f9d3c78d7b40) Thanks [@joshgillies](https://github.com/joshgillies)! - Simplify `/prefactor setup`. Browser sign-in is now the first option, and while pi waits for approval it shows only the sign-in link, clickable in terminals that support hyperlinks, and the code to approve. The QR code is gone, because pi cut it to a few rows and it could not be scanned. Choosing the agent now asks whether to create a new agent, with a name and description you can change, or use an existing one, picked from a list you can filter by typing. `@earendil-works/pi-tui` is now a peer dependency, supplied by pi.

- [#95](https://github.com/prefactordev/typescript-sdk/pull/95) [`90ebd69`](https://github.com/prefactordev/typescript-sdk/commit/90ebd698505a67147dc308ae6c2db0c5ed8062cb) Thanks [@joshgillies](https://github.com/joshgillies)! - Fix `pi install npm:@prefactor/pi`, which installed an extension that failed to load with "Cannot find module 'zod'". pi installs packages without their peer dependencies, so `zod`, a peer dependency of `@prefactor/core`, was never installed; `@prefactor/pi` now depends on it directly.

  Declare pi 0.99.0 as the lowest supported release in the peer dependencies on `@earendil-works/pi-coding-agent` and `@earendil-works/pi-tui`, which accepted any version before. pi 0.99.0 is the first release that reports everything the extension records, including which tool made a nested tool call. The README now states the supported pi version.
